# Editor UX

**Date:** 2026-02-14
**Participants:** lilbunnyrabbit, Claude
**Related:** [Token System Design](/docs/brainstorm/2026-02-14_token-system-design.md), [Emotion System](/docs/brainstorm/2026-02-14_emotion-system.md), [Reader Engine](/docs/brainstorm/2026-02-14_reader-engine.md)

## Context

The editor is where authors create Speed Books — writing text and assigning emotions/timing/effects to tokens. The current v2 approach is basic: text is parsed into tokens displayed as a flowing document, click a token to set its emotion. This works but is tedious at scale (a 4000-word Speed Book means potentially 4000 individual clicks) and lacks visual feedback.

The challenge: make it fast, intuitive, and visual without overcomplicating the interface.

---

## Key Insight: Most Words Won't Have Emotions

A critical realization that reframes the whole problem: **most words in a Speed Book will remain neutral.** Emotions are annotations on key moments — a 4000-word Speed Book might have 200-400 emotionally marked tokens. The editor doesn't need to make it easy to tag every word; it needs to make it easy to:

1. **Write/paste text** — Get words into the system quickly
2. **Identify key moments** — Find the words that deserve emotional annotation
3. **Apply emotions efficiently** — Tag those moments with minimal friction
4. **Preview the result** — See how it feels before publishing

---

## Proposed Approaches

### 1. Paint/Brush Mode (Like an Artist)

**Concept:** Select an emotion, then "paint" it across tokens by clicking/dragging — like a highlighter or a paintbrush tool.

**How it works:**
- Pick an emotion from the palette (the 2D emotion picker or preset buttons)
- Click a single token to apply, or click-and-drag across a range
- The emotion "brush" stays active — keep clicking/dragging to apply to more words
- An eraser mode to clear emotions back to neutral
- Brush size could allow painting multiple lines at once

**Why it's good:**
- Extremely intuitive — everyone understands paintbrush tools
- Fast for applying the same emotion to multiple consecutive words
- Feels creative and artistic, matching the "authoring an experience" vibe
- Minimal UI — just a palette and the text

**User reaction:** Really liked this idea — "like an artist."

---

### 2. Editing Modes (Write / Emotion / Timing / Preview)

**Concept:** Separate the editing experience into distinct modes, each focused on one concern.

| Mode | Focus | What You See |
|------|-------|-------------|
| **Write** | Text content | Plain text editor, no emotion UI |
| **Emotion** | Assigning emotions | Tokens colored/tagged by emotion, picker active |
| **Timing** | Duration/pacing | Timeline view, duration handles on tokens |
| **Preview** | Full playback | RSVP reader with all effects |

**Why it's good:**
- Reduces cognitive load — focus on one thing at a time
- Each mode can have a specialized, optimized UI
- Mirrors professional tools (video editors have timeline/preview/source modes)
- Write mode feels like a normal text editor — low barrier to entry

---

### 3. Inline Preview

**Concept:** The text in the editor itself reflects the emotion styling in real-time. As you assign emotions, the text visually changes (weight, size, opacity) right in the flowing document.

**Why it's good:**
- Instant visual feedback — see how it looks while you work
- No context switching to a preview panel
- Helps identify emotional "rhythm" in the text at a glance
- Natural extension of what's already happening

---

### 4. Properties Panel (Inspector)

**Concept:** A side panel that shows and edits all properties of the selected token(s). Select one or more tokens, and the panel shows their emotion, timing, effects, and raw style overrides.

**How it works:**
- Click a token → panel shows its properties
- Shift-click or drag-select multiple tokens → panel shows shared/mixed values
- Edit any property in the panel → applies to all selected tokens
- Quick preset buttons at the top of the panel for common emotions

**Why it's good:**
- Familiar pattern (design tools like Figma, code editors)
- Supports fine-grained control when needed
- Works well alongside paint mode — paint broadly, then refine in the panel
- Can show all raw style values for power users

**User reaction:** Liked the combination of properties panel with timeline view.

---

### 5. Timeline View

**Concept:** A horizontal timeline below the text showing tokens as blocks. Width represents duration. Emotion is shown as color/icon. Drag to resize blocks (change timing), drag emotions onto blocks.

```
Text:    The   forest  was   dark   and   silent
Timeline: [──][────][──][══════][──][════════]
                         ↑ wider = longer display time
```

**Why it's good:**
- Timing is immediately visible — long pauses, fast sections at a glance
- Familiar pattern (video/audio editors, animation tools)
- Drag-to-resize is intuitive for timing adjustments
- Can zoom in/out to see different levels of detail

**User reaction:** Liked the timeline concept for timings and animations, but unsure about wanting a literal timeline. Prefers a combination of properties panel and timeline — perhaps a hybrid where timing/animation properties are shown visually but within a properties-style panel rather than a full DAW-like timeline.

---

### 6. AI First Pass

**Concept:** After writing/pasting text, an AI suggests emotions for key moments. The author reviews and adjusts.

**How it works:**
1. Author writes or pastes plain text
2. Clicks "Suggest Emotions"
3. AI highlights ~10-20% of tokens with suggested emotions
4. Author reviews: accept, reject, or modify each suggestion
5. Author adds their own annotations on top

**Why it's good:**
- Dramatically reduces the "blank canvas" problem
- AI handles the obvious moments (exclamation marks, dialogue tags, etc.)
- Author retains full creative control
- Could learn from the author's style over time

---

## Recommended Phasing

| Phase | Features | Rationale |
|-------|----------|-----------|
| **MVP** | Write mode + click-to-select + emotion picker + inline preview | Get the basics working, validate the flow |
| **Phase 2** | Paint/brush mode + properties panel | Enable efficient emotion assignment at scale |
| **Phase 3** | Timeline/timing view (hybrid with properties panel) | Visual timing control |
| **Phase 4** | AI suggestions + advanced features | Polish and automation |

---

## Key Takeaways

1. **Most words stay neutral** — the editor should optimize for annotating key moments, not tagging every word
2. **Paint/brush mode** is the most promising interaction pattern for emotion assignment
3. **Properties panel + timeline hybrid** for timing and fine-tuning — showing timing visually without committing to a full DAW-like timeline
4. **Inline preview** should be present from day one — immediate visual feedback is essential
5. **Editing modes** help manage complexity as features are added
6. **AI suggestions** are a nice-to-have that dramatically improves the authoring experience

## User Preferences

- Likes the paintbrush/artist metaphor strongly
- Wants timeline-like visibility for timing but not necessarily a full literal timeline
- Prefers a combination of properties panel and timeline concepts
- Wants to revisit these ideas during actual implementation
